# Shared Life Topics — cumulative GPT update 1.10

This package extends the existing GPT with the unchanged 23-topic/seven-probe
development menu. It is separately optional and unscored. It does not add a
mandatory interview, reopen completed interviews or change historical scores.

The preceding 26 October shared-evidence package is recorded as installed by
the owner's “done continue” report. This successor package is a prepared update;
its existence does not mean the private GPT or live backend was updated.

## When to install

Use this package with the verified Life Patterns Action 1.10 backend. The new
instructions request capability information on the normal review retrieval;
the shared supplement is offered only when the saved ready review reports it
available. The older installed GPT remains supported by the additive backend.
No new GPT, bearer token, project or paid service is needed.

If an interview is in progress, obtain its source/recovery backup before changing
configuration. Keep the existing GPT and conversation.

1. Replace Instructions with `INSTRUCTIONS-life-patterns-v1.10.txt`.
2. In Knowledge, replace `ACTION-HANDOFF-GUIDE-v1.md`. Add
   `POST-REVIEW-OPTIONAL-MODULES-v1.md` and `SHARED-LIFE-TOPICS-v3.json`.
   The complete set of thirteen Knowledge files is included; the other ten are
   unchanged from the installed 26 October package.
3. Replace the Action schema with `ACTION-life-patterns-submission-openapi.yaml`,
   retaining the existing service URL and private bearer configuration. Save.

Upload individual files from `knowledge/`, not this ZIP, manifest, researcher
provenance, intake files or participant answers. No birth record or theory
mapping belongs in this GPT's Knowledge.

## Participant flow

The same primary interview and independent review run first. After confirmation,
primary freeze and the separate CF003 section, a participant finishing in GPT
may separately opt into Experience & Meaning and/or Shared Life Topics. A
Railway continuation uses the same optional modules in its private completion
page. Both routes make one final storage call for the complete chosen records.

Shared topics are participant-selected: at most five per sitting, plus at most
two justified conditional probes. Adequate prior answers are referenced rather
than repeated. A completed sitting is a stopping point. A later voluntary sitting
may cover different topics before final submission. Finalized submissions accept
only exact retries; this package does not add a later-append endpoint.

The primary record, CF003, Experience & Meaning and shared supplement remain
separate. Draft editing and exact source-excerpt selection are available before
the optional form is finally submitted. Original frozen interview evidence is
not edited by that form.

## What the checks establish

The package preserves all participant question wording. Its public bank excludes
the theoretical lineage in the researcher source. Local synthetic API and browser
checks cover consent, burden, source reuse, edits, missingness, storage, retries,
legacy response compatibility and mobile width. Those checks do not establish
human measurement validity, an untouched cohort, a live worker heartbeat, a
deployment or private-editor installation.

The separate trusted-intake metadata utility is researcher-side repository code,
not Knowledge and not a new GPT Action field. It records selected-study metadata
without exposing the birth tuple or profile/placement values to the interview.
