## Continuous-flow correction

An owner-supplied exact browser audit/recovery checkpoint showed why cross-area repetition could survive the earlier dynamic design: the old server state contained only the newest measurement-area conversation while older information survived mainly as compressed accepted patterns and coverage metadata. The private checkpoint is not committed.

Normal continuation now keeps **one accumulating server session**, so conversation, facts, corrections, and the hidden ledger survive area boundaries. Browser recovery also keeps bounded participant-answer memory and question-admission audit metadata.

For older exact snapshots that predate explicit answer memory, recovery seeds redundancy memory from accepted participant-authoritative wording plus any raw participant turns still present in the server snapshot. It cannot recreate raw answers that the older architecture never stored anywhere.

## Question usefulness admission

Questions are not exposed merely because a dimension remains incomplete.

Generated follow-ups pass a separate pre-send gate that can admit, replace, or stop the candidate. A displayed question must:

- target a genuinely missing discriminator;
- have materially different plausible answers that could change the person-specific picture or a still-open measurement distinction;
- be answerable from ordinary lived experience;
- not be semantically already answered;
- justify another participant turn.

Cross-area continuation gets an additional final admission/replacement pass using accumulated answer memory, accepted patterns, coverage, current conversation, and operative facts. Generic, normative, ordinary-human-default, vague, redundant, or questionnaire-for-its-own-sake prompts should therefore be replaced before display.

The admission rationale is stored only as audit/planning metadata, not as participant evidence.

## Participant flow

There is no routine `Continue interview` checkpoint. After local topic completion, direct participant-authored pattern recording, or successful judgment of a genuine inference, the app automatically chooses the next admitted question.

`Finish for now` remains persistently visible as the participant-controlled pause/exit. A Continue-style control is used only as a retry if next-question selection fails.

## Synthesis review

The ordinary always-visible textbox is now the **single participant text-entry channel** for inferred-synthesis feedback. It can carry disagreement, explanation, nuance, correction, missing context, or replacement wording.

Both `Close — I’ll explain what needs changing` and `Edit exact wording myself` are hidden. Backend distinctions do not require separate participant edit modes when one flexible text field can express the needed intent.

Distinct state-transition buttons remain only where they actually do something different: accept the inference, ask another useful question, reject/stop, or leave unresolved.
