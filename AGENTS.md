# AGENTS.md

## Mission
Build a reproducible, blinded Human Design birth-moment reverse-matching research harness from the specifications in this repository.

This repository tests two different questions and MUST keep them separate:

1. ENGINEERING VALIDATION: Can the decoder recover hidden chart/date/time states from responses generated by the same frozen model?
2. HUMAN VALIDATION: Do real human responses contain out-of-sample information about their actual birth-derived HD chart/date/time?

A successful synthetic test does not validate Human Design in humans.

## Non-negotiable research rules
- Never use the answer key during blind recovery.
- Never put secret answer keys under the decoder project root during a blind run.
- Hash/freeze predictions before answer-key reveal.
- Split human data by PERSON before question selection, mapping fitting, hyperparameter tuning, calibration, or evaluation.
- Post-hoc fitting on DEVELOPMENT humans is allowed and encouraged.
- Performance on those same development humans is not evidence of predictive validity.
- Keep a final untouched human test cohort.
- Report failures, ties, unresolved intervals, and negative results.
- Timezone is not independently identifiable from personality when local tuples resolve to the same UTC instant.
- Do not report a single minute when the scored state is stable across a wider interval.
- Missing support is not contradiction.
- Trauma/body-access variables may reduce measurement reliability; they may not turn a mismatch into support.
- No medical, legal, financial, or other high-stakes recommendations from Human Design.

## Implementation principles
- Deterministic chart computation.
- Exact boundary-event generation/root solving, not only coarse time grids.
- Reproducible random seeds.
- Versioned schemas and frozen mappings.
- Small modules with tests.
- Structured logs for every run.
- CLI first; API second.
- Use typed Python.
- Prefer pure functions for scoring.
- Cache chart states and ephemeris results.
- Never optimize evaluation cases.

## Required test discipline
Run unit tests and the relevant end-to-end blind test after changes.
Every claimed blind recovery must leave:
- experiment manifest,
- input hash,
- model hash,
- prediction file,
- prediction hash,
- timestamp,
- software versions,
- reveal status,
- evaluation file after reveal.

## Parallel work
Use independent worktrees/agents for separable implementation tracks when available.
Do not let the evaluator or decoder agent access secret keys.
Review and merge only after tests pass.

## When requirements are ambiguous
Do not invent a favorable HD interpretation.
Mark the mapping or behavior as `unresolved`, document it, and continue with the parts that are specified.
