# Active constraints
- Owner outcome: a stored complaint is not a delivered lesson. Required: authorized researcher can see route + issue + exact complaint and mark follow-up. Failure: data trapped in transcript.
- Historical integrity: frozen v7 and in-flight TF1 content must not be overwritten. Required: prospective candidate version with route crosswalk.
- Blinding/privacy: no birth/chart secrets, private source text, review IDs, credentials or participant identities in Git. Admin-only feedback may contain consented participant statements.
- Information gain: a rewrite must distinguish competing plausible behaviors and not merely ask for the obvious rational answer, force binary traits or repeat a settled distinction.
- Tool burden: no extra participant approval solely for instrument complaints. Batch through existing consented review request.
- Verification: focused tests before merge; distinguish code present, local tests, live deployment, and participant-experienced UX.
