# Full-survey participant package V2

Date: 2026-09-27. Assurance: Iteration. Parent goal remains a full, behavior-first survey usable for shared-model development; this package repairs collection/recovery/export UX without changing astronomical scoring.

## Problems observed in the first external participant record

The received participant record was behaviorally useful but exposed four avoidable collection weaknesses:

1. the distributed launcher depended on the interviewing ChatGPT successfully opening three separate GitHub authority files;
2. the resulting interview could drift into broad thematic/ad-hoc questions rather than preserving the canonical route identity and scene constraints needed for later mapping;
3. a later edited response document could lose route IDs, exact original wording, conditions, corrections, consent/review metadata and freeze provenance;
4. the end instructions said to "export" JSON without giving the participant a practical handoff path.

These observations do not show that every answer from that record is invalid. The repair preserves usable evidence, asks only material missing distinctions, and never imposes a complete-bank quota.

## V2 distribution rule

Distribute one self-contained participant file generated by `scripts/build_full_survey_participant_v2.py`. It embeds the exact frozen interview protocol, full scenario bank and evidence guide; GitHub access is not required in the participant chat.

The same file supports three modes:

- **new participant** — consent, then begin from the full bank;
- **existing old survey chat** — preserve all previous turns and continue only unresolved useful distinctions; do not restart;
- **lost old chat but response record exists** — attach the response record together with V2, import it as its declared source type, then continue without pretending the edited record is an original transcript.

## Question-admission hardening

Before rendering every scored/canonical question, the interviewer privately records the canonical route ID and checks the final wording against the existing admission gate. A generated repair remains tied to the canonical route and may change only context needed for answerability. Broad free-form thematic interviewing does not receive canonical evidence credit. Truly exploratory questions are explicitly labeled exploratory and remain outside canonical scoring/mapping until separately admitted.

Existing off-bank answers are not thrown away: they can support a neutral distinction through documented contextual equivalence or a narrower scope. Unknown stays unknown.

## Export handoff

At closeout ChatGPT creates the frozen JSON. The participant never has to know JSON, use account-data export, or manually reformat the chat. Preferred handoff is a downloadable `life-patterns-participant-export.json`; a fenced JSON block is the fallback. The participant sends that file/block to Joel.

## Non-goals

This package does not validate astrology, prove survey completeness, create new behavioral-to-chart meanings, require independent success of each tradition, change fitted weights/rules, or make a two-person fit. It preserves the existing owner-authorized development path.
