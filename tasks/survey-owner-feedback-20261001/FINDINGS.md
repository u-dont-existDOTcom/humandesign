# Owner test findings and bounded repairs

## Measurement failure

Observed: the v7 evidence guide deliberately permits a narrow, situation-specific reading for work energy, choosing familiar/new places, and calendar-tool switching. It explicitly forbids several broad interpretations the overall product could invite. Preserving that scope is correct, but collecting an adequate narrow answer does not establish that the question advances the broader objective of describing recurring behavioral tendencies.

The earlier calibration checkpoint already reported invalid, tautological and construct-mismatched questions. The same checkpoint documented seven rendered-question admission criteria, while verify_v7.py chiefly verifies that those rules and exact expected strings remain present. That is enforcement of an instruction contract, not evidence that real respondent-facing questions pass construct discrimination. The later GPT/HTTP tests and code review primarily established faithful collection and transport. They could not establish population discrimination or cross-context generalization.

The causal gap is objective-to-item alignment, not a missing instruction to reason harder. An independently reviewed answer can still be an accurate answer to a low-information question. The runtime planner is also restricted to the frozen bank: a downstream review cannot automatically replace a weak construct contract with a new instrument.

Audit: all 79 existing routes individually reviewed. Provisional dispositions: 18 opening rewrites, 15 retained scoped questions, 41 genuinely conditional probes, 5 demoted practical/context probes. These are design judgments, not empirical proportions. The replacement draft uses direct usual-pattern questions with aligned optional examples. Novelty, predictability, home preference, practical change benefits and familiarity cost remain separate. No requirement to produce a fresh confirming anecdote follows an adequate scoped self-report.

## Recovery failure

An earlier delivered source file contained only a September 16 reconstructed thread, not the later completed scenario survey. The later 79-answer source measurement was recovered and matched to its pre-existing freeze manifest. A source-only file preserving all question/answer strings, original versions and separately labeled process feedback was created privately for the owner. No participant text, private path or new participant-specific digest is published here. Historical question versions are retained; no answer is silently recoded under changed wording.

## Transport failure

The exact reported response comes from the RequestValidationError handler before storage. The handler formerly discarded field paths/types and returned only "Invalid fields". That prevents diagnosing which required request field failed. The actual rejected payload was not supplied, so its exact fault remains unknown.

The bounded repair adds safe field paths/codes/hints to both a structured error list and the detail string, without returning input values, arbitrary user-controlled keys, exception messages or validator context. This also serves clients that flatten responses to detail only. Required request fields, consent, freeze, source integrity and idempotency are not weakened. The schema now gives a complete synthetic example of the exact three-field start-review envelope.

The GPT instruction chain now requires an exact unfrozen candidate backup and actual file link before the first review call, followed by the requested approval sentence. Failure must return the preserved backup and a safe diagnostic artifact, never only an error paragraph. A missing record is not fabricated to satisfy the rule.

## Progress and layout

A short stage/count footer follows each question, with a separator and blank line. It gives actual imported/new answer counts, current stage and currently planned useful remaining topics, not a percentage based on administering all 79 routes or 73 facets. Three secondary questions may legitimately use a fixed denominator. No unsupported time estimate is introduced.

The footer moves nonessential content below the question and may reduce native scroll-control overlap. This is not custom CSS, a repair of ChatGPT's button, or a verified native-client result. The installed GPT still requires the owner's update and direct test.
