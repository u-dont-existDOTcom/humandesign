# Live pilot repair — M09 preserved-value probe — 2026-09-21

## Finding

The live follow-up:

> Suppose you do have enough time to switch. Is there anything about the old system itself that would still make you want to keep it?

failed because the old system is unspecified. The respondent cannot identify what is worth preserving without knowing any of its actual properties.

The original M09 scene can support a change-condition such as switching cost or available time, but it does not by itself supply enough detail to elicit `X06.preserved_value`.

## Disposition

- Treat the live response “how would I know unless I see it?” as design feedback, not trait evidence.
- Keep the already supplied change condition: available time to switch matters.
- Leave `X06.preserved_value` unresolved for this participant.
- Do not infer attachment to old systems, resistance to novelty, or indifference to preserved value.

## Better routes

Use one of these only if the distinction remains useful:

1. A concrete matched tradeoff with named properties on both old and new systems.
2. A real tool the respondent actually uses, asking what specific property they would not want to lose.

Avoid asking for abstract virtues of an unspecified incumbent system.
