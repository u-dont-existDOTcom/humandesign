# Numerology Overlay Protocol

Status: experimental symbolic overlay. It is **not** part of the current AstroHD natal score, V4.3 NetInformation, AstroRRF score, or relationship compatibility score unless a later frozen model explicitly admits it.

## Purpose

Test whether conventional Pythagorean numerology contributes reproducible, incremental information beyond the existing astrology and Human Design layers.

Numerology must remain identifiable as its own layer during testing so that a visually compelling retrospective fit cannot silently inflate astrology/HD evidence. **This separation is an evaluation requirement, not a permanent architecture commitment.** The intended experiment is explicitly allowed to conclude that astrology is materially more accurate when numerology is incorporated, in which case a later frozen fused model should be built and tested.

## Source convention

V1 uses one declared Pythagorean/Decoz-style convention consistently.

### Fixed birth-date numbers

Calculate from the recorded civil birth date:

- Life Path;
- Birthday number;
- Attitude / Sun number;
- Period cycles;
- Pinnacle cycles;
- Challenge numbers;
- Personal Year / Month / Day cycles.

Preserve useful compound numbers in reports, but also carry the reduced value used by the declared rule. Do not switch reduction rules after seeing an outcome.

### Name numbers

The primary identity profile uses the full birth name:

- Expression / Destiny;
- Soul Urge / Heart's Desire;
- Personality.

Vowels and consonants must be defined by the frozen letter convention. V1 treats Y as a consonant unless a later source-grounded revision explicitly defines contextual Y handling.

### Changed names and nicknames

A married, chosen, religious, pen, stage, or commonly used name is a **time-stamped identity overlay**, not a replacement for the birth-name profile.

A nickname is a separate use-name layer.

A changed-name layer may begin only when the person actually starts using that name. It must never be projected backward into years before adoption.

For relationship research, a partner-derived married surname is mechanically downstream of the relationship itself. Similarity created by adopting a partner's surname is therefore **not independent evidence that the pair was compatible or destined**. It may be studied as an identity-change marker, but it must not be double-counted as pair evidence.

## Progressive / timing layer

V1 includes four timing families.

### Personal cycles

Personal Year, Month, and Day use the frozen birth-date formula. Personal Years are calendar-linked; reports should preserve the exact convention used for overlap around the birthday.

### Pinnacles and Period cycles

Treat these as long-term background chapters. Preserve exact transition ages from the frozen formula.

If the source convention describes a transition as building before the formal boundary, predeclare that lead-in width before evaluating events. Do not widen a transition window after seeing the target event.

### Birth-name Transits

Transit letters are calculated from the full birth name:

- first name -> Physical Transit;
- all middle names concatenated -> Mental Transit;
- last name -> Spiritual Transit.

Each letter remains active for a number of years equal to its Pythagorean value; after the end of a name component, cycle back to the first letter.

Transit/Essence timing uses the birth name in V1. A later current-name timing model would be a separate version, not a silent substitution.

### Essence cycles

For each birthday-to-birthday age interval, sum the active Physical, Mental, and Spiritual Transit values and preserve both compound and reduced Essence.

## Relationship layer

A relationship profile may compare both partners' five core numbers:

- Life Path;
- Birthday;
- Expression;
- Soul Urge;
- Personality.

Do not reduce the pair to a generic soulmate percentage.

Structural coincidences must be decomposed for mathematical dependence. For example, Expression is derived from the same name letters that produce Soul Urge and Personality, so a matching Expression plus matching component numbers cannot be counted as three statistically independent coincidences.

## Development, nulls, and prospective testing

Known owner/partner cases are DEVELOPMENT cases.

Retrospective numerology fit may be used to refine:

- which conventional quantities to calculate;
- reporting language;
- candidate prospective hypotheses;
- null-model design.

It is not validation on that same person or couple.

For event timing:

1. calculate/freeze the numerology timeline without event labels;
2. calculate/freeze the astrology/HD timing layer independently;
3. only then reveal or score the event history;
4. report numerology-only, astrology-only, and combined results separately;
5. preserve misses and low-impact events, not only striking hits.

For future predictions, freeze the numerology windows before the outcome occurs and do not slide them afterward.

## Combined AstroHD + numerology model

Numerology is initially an **overlay**, not another free point in a stacked score. The overlay phase exists to measure what numerology contributes. If it supplies repeatable information that repairs astrology's misses or materially improves discrimination, the intended next step is to **fuse the systems into one model** rather than keep them artificially separate.

The first combined evaluation must report:

1. astrology-only;
2. Human-Design-only where applicable;
3. numerology-only;
4. existing AstroHD combination;
5. AstroHD + numerology.

A combined score may be promoted when numerology adds useful incremental discrimination over astrology/HD on development data and that gain survives testing on new people/events/couples. Candidate fusion models may be fitted on declared DEVELOPMENT cases; they must be labeled development rather than blocked until out-of-sample proof exists. Out-of-sample performance determines whether the fusion is validated/generalizable, not whether it may be explored.

Do not award extra evidence merely because multiple symbolic systems can be interpreted to describe the same known event. Their feature families, fitting exposure, and mathematical dependencies must be explicit.

## Rarity / "strikingness"

Do not infer statistical rarity from a pattern merely because it sounds specific.

For name-number symmetry or relationship-number coincidences:

- define the matching rule before measuring rarity;
- use an appropriate comparison population or clearly label a simple combinatorial calculation as a toy null;
- account for dependent quantities derived from the same letters;
- account for multiple comparisons across many available numbers;
- keep changed-name effects created by the relationship separate from independent pre-relationship matches.

## Claim boundary

Numerology is treated here as a testable symbolic hypothesis. The protocol can measure reproducibility, discrimination, incremental value, and prospective hits/misses; it does not assume that numerological mechanisms are scientifically established.
