# Survey-v2 Human Measurement Methods Check v1.0.0

Status: candidate freeze pending Extra High verification and the single named Pro review.

## Scope

This package specifies the frozen semantics required to make one blinded convenience-sample natal DEVELOPMENT case executable once runtime implementation is separately authorized and accepted. It is not a validation result, population estimate, product-release basis, or evidence that Human Design predicts people. The V3.6 source is one clean one-off mapping family of 26 binary observables, not a complete canonical V4.3 mapping library.

## Independent conception

- Problem: a chart-derived categorical oracle lacked a defensible function from human narrative to scoreable observations.
- Mechanism: frozen directed codebooks, separate evidence custody, candidate-blind GPT classification, selective abstention, masked channel scoring, immutable pre-reveal locks, and exact rational ranking.
- Constraint: no new HD constructs, participant-informed revision, paid API use, or treatment of missing channel evidence as absence.
- Candidate insight: decompose the complete 36-channel set into independently observed binary labels while retaining one family weight.

## Bounded methods comparison

- Directed content analysis is adapted because codes are frozen from prior theory rather than induced from the participant. Symmetrical anchors, minimum evidence, and counterevidence are mandatory; no post-participant code development is allowed. See Hsieh & Shannon (2005), https://doi.org/10.1177/1049732305276687, and Gale et al. (2013), https://doi.org/10.1186/1471-2288-13-117.
- Multilabel representation is adapted, but raw Jaccard is not used. Jaccard would treat unobserved channels as negative evidence. The frozen rule uses masked binary decisions and macro exact agreement only over observed channels. See the scikit-learn multilabel metrics documentation: https://scikit-learn.org/stable/modules/generated/sklearn.metrics.jaccard_score.html.
- Reject-option classification is adapted: inadequate evidence, sub-threshold confidence, all-label ambiguity, and unsupported absence abstain instead of forcing a label. See Chow (1970), https://doi.org/10.1109/TIT.1970.1054406.
- Classifier agreement is measured rather than assumed. The first locked output is confirmatory; one isolated same-model repeat is diagnostic and cannot change the score. See Artstein & Poesio (2008), https://aclanthology.org/J08-4004/.
- Confidence is restricted to an ordinal rubric gate and is never presented as a calibrated probability. See Guo et al. (2017), https://proceedings.mlr.press/v70/guo17a.html.
- Predictions, prompts, labels, thresholds, scoring, stopping, omissions, and fixture expectations are hash-locked before participant evidence. Post-reveal changes require a future version. See Nosek et al. (2018), https://doi.org/10.1073/pnas.1708274114.

## Owner-source corrections

Prior HD/astrology exposure alone does not exclude a participant; it is recorded for stratification because the participant supplies measured narrative. H1 requires an independently clean author of interpretation or construct content and therefore uses the owner-approved contamination rule: shallow/incidental exposure is eligible, substantial semantic/technical familiarity requires blind GPT adjudication, and identity-defining/comprehensive or intentionally HD-derived framing is ineligible. Owner form testing is usability evidence only. Incremental spending is exactly $0; GPT adjudication/classification must use a fresh candidate-blind ChatGPT Pro/Codex context under an included entitlement or the case remains blocked.

## Adequacy

- Operational adequacy: adequate for mechanical encoding only.
- Scientific adequacy: not yet frozen; pending faithful Extra High verification and the named Pro review.
- Release adequacy: not adequate; deployment and scientific human execution remain blocked.

The unresolved remainder is empirical: whether a person supplies stable evidence that GPT maps reliably to these frozen HD labels, and whether those labels rank the declared birth state unusually well. This package enables that question; it does not answer it.
